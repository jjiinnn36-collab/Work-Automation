# ADR-0005 지점 이름은 '달성한 것', 버튼은 '행동'

- 상태: 채택
- 날짜: 2026-09-16
- 관련: AC-W49~W52, AC-W70~W76 (웹 명세, 사용자 지시 2026-09-13)

## 맥락

코드의 단계 이름은 `납부 전 / 전표결재 / 납부완료` 처럼 **상태**였다.
사용자는 시안 검토에서 (1) 지점은 달성한 것으로 적고 `완료` 는 떼며, (2) 버튼·밑줄에는 해야 할 **행동**을 적으라고 정했다.
`납부 전` 에 파란 점을 두면 "이미 지나온 자리" 에 할 일이 있는 것처럼 읽힌다.

## 결정

| 흐름 | 지점 (stage 0 → 끝) | 다음 행동 (stage 0 기준부터) |
|---|---|---|
| 신고납부 | 신고서 작성 → 신고 → 전표발행 → 납부 | 신고완료 → 전표 발행 → 납부완료 |
| 납부만 | 고지서수령 → 전표발행 → 납부 | 전표 발행 → 납부완료 |
| 제출만 | 제출자료 작성 → 제출 | 제출하기 |

- `stage` 는 **마지막으로 끝낸 지점**의 번호. 파란 점과 버튼은 `stage + 1` 을 가리킨다.
- 다 끝나면 행동 자리에 `모두 끝났습니다`.
- 단계 번호(0,1,2…)는 그대로이므로 **진행 기록은 옮길 필요가 없다.** 이름만 바뀐다.
- 증빙 목록에 글자로 저장된 옛 이름은 스키마 2판 이관에서 새 이름으로 바꾼다 (`Stages.옛이름`).
  이미 디스크에 있는 파일 이름(`전표결재_20260910…pdf`)은 바꾸지 않는다 — 파일을 옮기면 경로가 끊긴다.
- 모든 화면(팝업·보드·웹)이 `Stages.For`, `Stages.다음행동` 한 곳을 쓴다.

## 결과

- 2026-09-15 에 만든 코너형 팝업 시안의 버튼 문구(`전표결재`)는 `전표 발행` 으로 바뀐다.

## 검증

`TestRunner` [5], [5b]; `WebTests` WEB-2 (`nextStage`, `nextAction`), WEB-9 (첨부 시점 지점 이름); `DbTests` DB-15 (옛 이름 이관).

## 개정 (2026-09-16)

사용자 요청으로 행동 문구 '신고하기' → '신고완료', '납부하기' → '납부완료'. 누르는 순간 그 일을 끝낸 것으로 기록되므로 완료형이 더 정확하다. '전표 발행', '제출하기' 는 그대로.
