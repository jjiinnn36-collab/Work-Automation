# ADR-0014 추적 시작 전 건은 흐리게, 진행중·진행예정은 밟은 단계로

- 상태: 채택
- 날짜: 2026-09-16
- 관련: 사용자 결정 Q1·Q3·Q4·Q6 (`docs/decisions-needed.md`), AC-W56, W82~W85, W31, W52

## 맥락

- Q1: 추적 시작일 이전 건을 화면에서 아예 뺐다. 연간 화면이 "그 해 전체 일정표" 로 쓰이는데 일부가 비어 보였다.
- Q3: 연간은 알림일 기준(알림일이 지났으면 진행중), 이번 달은 "끝나지 않은 건 전부 = 진행중" 이었다.
  명세(AC-W83)는 진행중 = `stage ≥ 1`, 진행예정 = `stage = 0` 이다. 같은 낱말이 두 화면에서 다른 뜻이었다.

## 결정

- 서버 `Env.OccurrencesOf` 는 시작일과 무관하게 그 해 발생 건을 모두 만들고, `Env.시작전(o)` 로 가린다.
  - 발생 건 자료에 `beforeStart`, 상태 문구 `추적 시작 전`, severity `before`.
  - **집계(진행중·진행예정·완료·기한 지남·금액 미확인·합계)에는 넣지 않는다.** 따로 `beforeStart` 건수를 준다.
  - 연간·이번 달의 **지난 건** 묶음(끝난 건 + 시작 전 건, 최근 것이 위)에 넣는다. 화면은 흐리게(불투명도 55%) 그린다.
  - 시작 전 건에는 행동 버튼·오늘은 대기·금액 [입력]·문서 열기를 보이지 않는다 (AC-W31, W52).
  - 받은 알림·팝업·이력은 그대로 시작 전 건을 다루지 않는다.
- 이번 달·연간이 같은 집계 규칙(`WebServer.집계`)을 쓴다. 겹치지 않는 네 칸:
  **완료** / **기한 지남**(기한이 지난 미완료) / **진행중**(한 단계라도 밟은 미완료) / **진행예정**(아직 안 밟은 미완료).
  화면의 `yearStatus` 도 같은 규칙이다.
- 이번 달 집계 칸: 진행중 · 진행예정 · 완료 · 기한 지남 · 이 달 납부 합계. 목록 머리말은 `남은 건 n · 진행중 n · 진행예정 n` / `지난 건`.
- Q4 첫 화면은 받은 알림 그대로, Q6 팝업 오른쪽 여백 12px 그대로.
