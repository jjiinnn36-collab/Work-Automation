# ADR-0006 스키마 2판 이관 절차와 금액규칙 고정/변동

- 상태: 채택
- 날짜: 2026-09-16
- 관련: AC-W25~W28, AC-W26a, AC-W92, AC-W103, AC-W33

## 맥락

1판 DB 에는 `schema_version` 값만 있고 칸을 늘리는 절차가 없었다.
명세가 요구하는 홈페이지 주소, 분할납부 묶음, 받은 문서/증빙 구분, 변경 기록(ADR-0004)에 칸이 필요하다.
금액규칙은 `고정·고지수령·전기확정÷4·수작업·해당없음` 다섯 값이었고, 사용자는 **고정/변동 둘만** 쓰기로 했다.

## 결정

### 이관 절차
- 파일을 열 때 1판 표를 `IF NOT EXISTS` 로 만든 뒤 `schema_version` 을 보고 **한 판씩** 올린다.
  새 파일도 같은 길을 밟으므로 "새로 만든 파일" 과 "옛 파일을 올린 결과" 가 같다.
- 각 판 올리기는 한 트랜잭션. 실패하면 1판 그대로 남는다.
- 자료(항목)가 있는 파일이면 올리기 전에 `자료폴더\backups\납부알림-v1-이관전-날짜시각.db` 사본을 만든다.
- 파일의 판이 프로그램보다 높으면 열지 않는다 (옛 exe 가 새 파일을 망가뜨리지 않게).

### 2판 내용
- `items` + `홈페이지명`, `홈페이지주소`, `묶음`
- `attachments` + `종류` (`증빙` / `받은문서`, 기본 증빙)
- `events` 표 (ADR-0004)
- 금액규칙: `고정` 이거나 **고정금액이 적혀 있으면 고정**, 나머지는 `변동`.
  (금액이 적힌 `수작업` 행을 변동으로 바꾸면 적어 둔 금액이 화면에서 사라지므로 고정으로 둔다.)
- 옛 단계 이름 → 새 이름 (ADR-0005)
- 묶음: id 가 `접두-두자리` 이고 기관·비용명이 같은 항목이 둘 이상이면 접두를 묶음 이름으로 (예: kofia-05…10 → `kofia`)

### 금액 규칙의 뜻 (`AmountRules`)
- **고정**: 마스터 `고정금액` 을 해마다 쓴다. 그 해 금액을 따로 넣으면 그것이 우선.
- **변동**: 마스터 금액을 쓰지 않는다. 그 해 금액(`amounts`)만 쓴다. 없으면 `미확인`.
- **제출만** 흐름: 금액 자체가 없다 (`미확인` 도 아님). 저장 시 고정금액을 비운다.
- 웹 항목 편집은 `고정/변동` 외 값을 400 으로 거절하고, 고정인데 금액이 없으면 거절한다.
- TSV 가져오기(옛 도구)는 옛 값을 같은 규칙으로 정규화한다.
- 팝업·보드·웹이 모두 `AmountRules.금액 / 미확인` 한 곳을 쓴다. 전에는 세 곳에 따로 있었다.

## 결과

- 치르는 값: `고지수령`(고지서 기다림) 과 `수작업`(직접 산정) 의 구분이 사라진다 → 필요하면 비고에 적는다 (명세에서 사용자에게 고지됨).
- 실제 자료 22건 기준: 고지수령 10·수작업 5·전기확정÷4 3 → 변동, 고정 2 → 고정, 해당없음 2(제출만) → 변동(금액 없음).
