# ADR-0011 받은 문서와 증빙, 홈페이지 바로가기, 기본 프로그램으로 열기

- 상태: 채택
- 날짜: 2026-09-16
- 관련: AC-W20~W22, AC-W92~W107

## 맥락

국세청 건은 홈택스로 가고, 계좌이체 건(감독분담금·협회비)은 받은 통보문을 열어 계좌를 봐야 한다.
증빙 목록은 한 종류라 "받은 고지서" 와 "처리 후 붙인 영수증" 이 섞였다.
브라우저는 xlsx·hwp 를 보여 주지 못하고, 임의의 로컬 파일을 열 수도 없다.

## 결정

- `attachments.종류` = `받은문서` | `증빙` (기본 증빙). 첨부 요청의 `kind` 로 정한다. 변경 기록 동작도 `문서첨부` / `첨부` 로 나뉜다.
- 항목에 `홈페이지명`·`홈페이지주소`. 주소는 **http/https 만** 받는다 — `javascript:` 가 링크로 박히면 누르는 순간 화면 안에서 스크립트가 돈다.
  주소만 넣고 이름을 비우면 이름은 `홈페이지`.
- 화면 규칙: 주소가 있으면 `[홈페이지명] ↗` 링크(새 창, `rel=noopener noreferrer`), 없으면 `문서 열기` → 받은 문서 목록.
  받은 문서가 하나면 바로 연다(AC-W107), 없으면 첨부하라고 안내(AC-W22).
- 미리보기: PDF·이미지는 대화상자 안 보기창(iframe)에서 (AC-W105).
  `GET /api/file` 은 PDF·이미지에는 `Content-Security-Policy: sandbox` 를 붙이지 않는다 —
  Chrome 은 sandbox 가 걸린 PDF 를 뷰어로 열지 않는다. 그 밖의 형식은 내려받기(attachment) + sandbox.
- 브라우저가 못 보여 주는 형식은 `POST /api/open` 이 **이 PC 의 기본 프로그램**으로 연다 (AC-W106).
  목록에 있고 증빙 폴더 안에 있는 파일만. POST 이므로 CSRF 머리글 규칙(ADR-0003)을 따른다.

## 결과

- 서버가 로컬 프로그램을 띄우는 경로가 생긴다. localhost·Host·CSRF 머리글 검사와 목록·폴더 제한으로
  "사용자가 붙인 파일을 사용자가 누를 때만" 열리게 묶었다.

## 검증

`WebTests` WEB-9 (파일 경로 차단), WEB-12 (주소 검증), WEB-15 (받은문서 첨부·열기·403·404).
