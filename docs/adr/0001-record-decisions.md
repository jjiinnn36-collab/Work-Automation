# ADR-0001 결정 기록 방식

- 상태: 채택
- 날짜: 2026-09-16

## 맥락

설계 결정이 대화·명세(`.omc/specs/`)·커밋 메시지에 흩어져 있다. 명세는 인터뷰 기록이라
나중에 바뀐 결정(예: TSV → SQLite)이 반영되지 않는다. 사용자는 자율 작업 결과를 뒤에 확인한다.

## 결정

- 되돌리기 어려운 결정마다 `docs/adr/NNNN-제목.md` 를 하나 쓴다.
  형식: 상태 / 날짜 / 맥락 / 결정 / 결과(좋은 점·치르는 값) / 검증(어떤 테스트가 지키는지).
- 사용자 판단이 필요한 것은 구현하지 않고 `docs/decisions-needed.md` 에 선택지와 추천을 적는다.
- 미구현 조사 결과는 `docs/production-gaps.md` 에 둔다.
- 커밋 하나는 기능 하나이며, 본문에 관련 ADR 번호와 추가된 테스트를 적는다.

## 결과

- 명세와 코드가 어긋날 때 무엇이 최신인지 ADR 날짜로 가린다. ADR 이 명세보다 우선한다.
