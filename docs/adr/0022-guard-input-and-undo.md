# ADR-0022 입력 잃음·잘못 누름 막기 — 닫기 확인, 연달아 누르기, 되돌리기 알림, 대기 취소, 덮어쓰기 확인

- 상태: 채택
- 날짜: 2026-09-17
- 요청: ADR-0021 점검 목록 중 "1,4,5,6만 수정" + "2,3번도 추가"

## 결정

| # | 어디 | 바꾼 것 |
|---|---|---|
| 1 | 웹 항목·금액·회차 금액 창 | 바뀐 내용이 있을 때 ✕·Esc·바깥 누르기·취소로 닫으면 "저장하지 않고 닫을까요?" (`hooks/use-close-guard.ts`). 회차 창에서 연도를 바꿀 때 입력이 있으면 같은 확인 후 비움. 금액 창의 "모든 회차" 로 옮길 때도 확인 |

| 6 | 웹 회차 금액 한 번에 | 바뀌는 회차를 최대 5개 + "외 N건" 으로 보여 주고 확인 |

## 세부

- 대기 취소는 **그 건의 마지막 기록이 '대기'** 이고 오늘 확인한 경우에만 받는다(`Store.대기취소`).
  진행도 오늘 확인 표시를 남기므로, 확인 표시만 보면 진행한 건의 표시를 지울 수 있었다.
  목록 응답은 `Store.마지막동작()` 한 번의 질의로 건마다 계산한다.
- 닫기 확인 창의 버튼을 누른 동작이 뒤 창에 '바깥 누르기' 로 전해져 확인이 다시 뜨던 문제:
  확인 창 안에서 온 닫기 요청은 무시하고, 확인 창이 닫힌 뒤 0.4초 동안 닫기 요청을 받지 않는다.
- 저장이 끝나 닫을 때는 확인하지 않는다.

## 검증

- DB-21(대기 취소 조건·마지막 동작), WEB-18(`/api/undefer` 200·409·기록 출처), GUI-14(연달아 누르기), 화면 규칙 12묶음.
- 실제 웹 화면: 항목 추가 창에서 입력 → Esc → 확인 창 → 취소(창 유지·입력 유지) → Esc → 닫기(둘 다 닫힘). 저장은 하지 않음.
- 되돌리기 알림 버튼은 실제 자료를 바꾸게 되어 화면에서 누르지 않았다(타입 검사·WEB-18 로 대신).
