# ADR-0015 사용자설정 진행흐름, 항목 id 자동 생성, 팝업 접기, 항목 창 옮기기

- 상태: 채택
- 날짜: 2026-09-16
- 요청: "팝업창은 최소화버튼을 작게 만들어서 최소화시키면 제목란만 보이게 / 항목추가 창을 이동 가능하게 / id 를 자동으로 생성 / 진행흐름에 사용자설정을 추가해 단계 갯수·진행흐름·기한·금액을 입력"

## 1. 사용자설정 진행흐름

### 결정
- `Flow` 에 `사용자설정` 을 더한다. 단계는 항목마다 따로 가진다.
  - `PaymentItem.사용자단계` — 지점 이름 2~8개. 첫 칸은 시작 지점(ADR-0005 와 같은 모양).
  - `PaymentItem.사용자행동` — 그 지점에 도달할 때 누르는 버튼 문구. 비우면 지점 이름을 쓴다.
  - `PaymentItem.금액없음` — 돈을 내지 않는 건(제출·보고). 제출만 흐름과 같게 금액 칸을 끈다.
- 기한(월·일·알림 영업일)과 금액(고정/변동, 고정금액)은 기존 칸을 그대로 쓴다. 흐름만 새로 정하면 되므로 따로 만들지 않았다.
- 단계를 묻는 모든 곳을 `Stages.For(Flow)` 에서 `Stages.For(PaymentItem)` 으로 바꿨다 —
  스케줄러(완료 판정), DB 진행·되돌리기, 웹 DTO, 첨부 단계 이름, 팝업, 월간 보드.
  `Db.Advance/Revert` 는 단계 목록을 받는 판을 더하고 옛 `Flow` 판은 그 판을 부른다.
- 검사 규칙은 `Stages.단계검사` 하나. 이름 빈칸·중복·20자 초과·`|`·줄바꿈 거절. 화면도 같은 규칙으로 먼저 알린다.

### 저장 (스키마 3판)
- items 에 `단계정의 TEXT`(줄마다 `지점|버튼문구`), `금액없음 INTEGER` 를 더한다.
- 2판 표의 `CHECK(진행흐름 IN (...))` 에 새 값을 넣어야 하는데 SQLite 는 CHECK 를 고칠 수 없다.
  그래서 `items_v3` 를 만들어 옮기고 이름을 바꾼다. 한 트랜잭션이고, 자료가 있으면 이관 전 사본을 남긴다(ADR-0006).
- 별도 표(item_stages)도 생각했지만, 단계 목록은 항목과 늘 함께 읽고 쓰며 크기가 작아 한 칸이 단순하다.

### 이미 진행한 건의 단계를 줄이면
- 진행 상태의 단계 번호는 그대로 둔다. 화면·팝업은 마지막 지점으로 잘라 보여 주고(끝난 건),
  되돌리기는 마지막 지점부터 한 칸씩 내려간다. 기록은 지우지 않는다.

## 2. 항목 id 자동 생성

### 결정
- 새 항목을 id 없이 보내면 서버가 `item-0001` 꼴로 만든다. 화면에서 id 입력칸을 없앴다(수정 창 설명에만 보인다).
- 번호는 `meta.next_item_no` 에 적어 두어 **지운 항목의 번호를 다시 쓰지 않는다**.
  항목을 지워도 진행 기록·금액·증빙은 id 로 남기 때문에(ADR-0004), 번호를 재사용하면 새 항목에 옛 기록이 붙는다.
- items·status·amounts·attachments·events 에 이미 있는 id 와 분할 회차(`item-0003-05`)가 쓰는 번호도 건너뛴다.
- 분할납부는 만든 번호를 묶음 이름으로 쓰고 회차는 `번호-월` 이다(ADR-0010 그대로).
- id 를 직접 보내는 요청(시험·옛 화면)은 계속 받는다. 형식 검사도 그대로.

## 3. 팝업 접기

- 머리 오른쪽에 작은 `▾` 버튼(24×22). 누르면 높이 44px(머리)만 남고 아래 끝은 작업 표시줄에 붙은 채다.
  `▴` 나 제목을 누르면 다시 펼친다.
- 접기는 닫기가 아니다. 고르지 않은 건이 남아 있으면 계속 떠 있고 닫기 규칙(ADR-0009)은 그대로다.
- Windows 10 처럼 시스템 둥근 모서리가 없으면 창 모양(Region)을 크기에 맞춰 다시 깎는다.
- 시험: Smoke GUI-3 (접힌 높이, 아래 끝 고정, 폭 유지, 버튼 문구).

## 4. 항목 창 옮기기

- 항목 추가·수정 창의 머리(제목 줄)를 끌면 창이 따라 움직인다(`hooks/use-draggable.ts`).
  가운데에서 옮긴 거리만 들고 있다가 다시 열면 가운데로 돌아온다. 머리가 화면 밖으로 나가지 않게 가둔다.
- shadcn Dialog 는 그대로 쓰고 `left/top` 만 바꾼다 — 열림 애니메이션(transform)과 겹치지 않게.
