# ADR-0015 사용자설정 진행흐름, 항목 id 자동 생성, 팝업 접기, 항목 창 옮기기

- 상태: 채택
- 날짜: 2026-09-16
- 요청: "팝업창은 최소화버튼을 작게 만들어서 최소화시키면 제목란만 보이게 / 항목추가 창을 이동 가능하게 / id 를 자동으로 생성 / 진행흐름에 사용자설정을 추가해 단계 갯수·진행흐름·기한·금액을 입력"

## 1. 사용자설정 진행흐름

### 결정
- `Flow` 에 `사용자설정` 을 더한다. 단계는 항목마다 따로 가진다.
  - `PaymentItem.사용자단계` — 지점 이름 2~8개. 첫 칸은 시작 지점(ADR-0005 와 같은 모양).
  - `PaymentItem.사용자행동` — 그 지점에 도달할 때 누르는 버튼 문구. 비우면 지점 이름을 쓴다.
  - `PaymentItem.금액없음` — 돈을 내지 않는 건(제출·보고). 제출만 흐름과 같게 금액 칸을 끈다.
- 기한(월·일·알림 영업일)과 금액(고정/변동, 고정금액)은 기존 칸을 그대로 쓴다. 흐름만 새로 정하면 되므로 따로 만들지 않았다.
- 단계를 묻는 모든 곳을 `Stages.For(Flow)` 에서 `Stages.For(PaymentItem)` 으로 바꿨다 —
  스케줄러(완료 판정), DB 진행·되돌리기, 웹 DTO, 첨부 단계 이름, 팝업, 월간 보드.
  `Db.Advance/Revert` 는 단계 목록을 받는 판을 더하고 옛 `Flow` 판은 그 판을 부른다.
- 검사 규칙은 `Stages.단계검사` 하나. 이름 빈칸·중복·20자 초과·`|`·줄바꿈 거절. 화면도 같은 규칙으로 먼저 알린다.

### 저장 (스키마 3판)
- items 에 `단계정의 TEXT`(줄마다 `지점|버튼문구`), `금액없음 INTEGER` 를 더한다.
- 2판 표의 `CHECK(진행흐름 IN (...))` 에 새 값을 넣어야 하는데 SQLite 는 CHECK 를 고칠 수 없다.
  그래서 `items_v3` 를 만들어 옮기고 이름을 바꾼다. 한 트랜잭션이고, 자료가 있으면 이관 전 사본을 남긴다(ADR-0006).
- 별도 표(item_stages)도 생각했지만, 단계 목록은 항목과 늘 함께 읽고 쓰며 크기가 작아 한 칸이 단순하다.

### 이미 진행한 건의 단계를 줄이면
- 진행 상태의 단계 번호는 그대로 둔다. 화면·팝업은 마지막 지점으로 잘라 보여 주고(끝난 건),
  되돌리기는 마지막 지점부터 한 칸씩 내려간다. 기록은 지우지 않는다.

## 2. 항목 id 자동 생성

### 결정
- 새 항목을 id 없이 보내면 서버가 `item-0001` 꼴로 만든다. 화면에서 id 입력칸을 없앴다(수정 창 설명에만 보인다).
- 번호는 `meta.next_item_no` 에 적어 두어 **지운 항목의 번호를 다시 쓰지 않는다**.
  항목을 지워도 진행 기록·금액·증빙은 id 로 남기 때문에(ADR-0004), 번호를 재사용하면 새 항목에 옛 기록이 붙는다.
- items·status·amounts·attachments·events 에 이미 있는 id 와 분할 회차(`item-0003-05`)가 쓰는 번호도 건너뛴다.
- 분할납부는 만든 번호를 묶음 이름으로 쓰고 회차는 `번호-월` 이다(ADR-0010 그대로).
- id 를 직접 보내는 요청(시험·옛 화면)은 계속 받는다. 형식 검사도 그대로.

## 3. 팝업 접기

- 머리 오른쪽에 작은 `▾` 버튼(24×22). 누르면 높이 44px(머리)만 남고 아래 끝은 작업 표시줄에 붙은 채다.
  `▴` 나 제목을 누르면 다시 펼친다.
- 접기는 닫기가 아니다. 고르지 않은 건이 남아 있으면 계속 떠 있고 닫기 규칙(ADR-0009)은 그대로다.
- Windows 10 처럼 시스템 둥근 모서리가 없으면 창 모양(Region)을 크기에 맞춰 다시 깎는다.
- 시험: Smoke GUI-3 (접힌 높이, 아래 끝 고정, 폭 유지, 버튼 문구).

## 3-1. 팝업 설정 버튼 (웹 화면 열기)

- 접기 버튼 왼쪽에 톱니 버튼. 누르면 자기 exe 를 `--web` 으로 실행한다.
  웹 서버가 이미 떠 있으면 그 주소로 브라우저만 열고(기록: "이미 떠 있는 웹 화면을 엽니다"),
  꺼져 있으면 서버(알림 영역 아이콘)를 띄운 뒤 연다 — 기존 `RunWeb` 규칙을 그대로 쓴다.
- 이모지 ⚙ 는 컬러 글꼴로 까맣게 뭉개져 Windows 기호 글꼴 `Segoe MDL2 Assets` 의 톱니(U+E713)를 쓴다.
  글꼴이 없는 PC 는 '설정' 글자 버튼.
- 머리가 좁아져 날짜를 `5/27 (목)` 으로 줄이고, `⚠ 자료 확인` 이 건수 라벨에 가려지지 않게 앞으로 올렸다.
- 시험: Smoke GUI-4 (버튼 있음, 누르면 웹 열기 한 번, 연결 없어도 오류 없음, 접기 버튼 왼쪽).

## 3-2. ⋯ 메뉴 모양

- 사용자 제보: ⋯ 를 눌러 메뉴가 열리면 이상한 사각 외곽선이 보인다.
- 원인: ContextMenuStrip 이 Windows 기본 그리기(ToolStripProfessionalRenderer)라
  각진 1px 테두리, 왼쪽 회색 아이콘 여백 띠, 파란 선택 강조로 그려져 둥근 팝업과 어긋났다. 버튼 자체는 문제없음.
- 결정: `Ui.메뉴꾸미기` — 직접 그리기(`메뉴그리기`): 흰 바탕, 아이콘·체크 여백 없음,
  선택 항목은 안쪽으로 들인 둥근 사각형(양피지색), 구분선은 연한 선, 흐린 항목은 회색 글씨.
  Windows 11 은 DWM 으로 메뉴 창 모서리를 둥글게 하고 테두리를 맡기며, 그 밖에는 연한 사각 테두리를 그린다.
- 시험: Smoke GUI-5 (아이콘 여백 없음, 기본 그리기 아님, 흰 바탕).

## 3-3. 팝업 버튼 전체 검수와 통일

- 사용자 요청: ⋯ 메뉴의 사각 외곽선 같은 현상을 모든 버튼에서 검수하고 통일할 것.
- 검수 방법: 데모 팝업의 버튼 8개(▾, 설정, 진행, 대기, ⋯, ‹, ›, 닫기)를 실제 마우스로
  보통·올림·누름·마우스 뗀 뒤 상태로 만들고, Tab 으로 키보드 초점을 켠 창을 PrintWindow 로 떠서 4배로 비교.
  원인을 가리려고 PillButton 을 격자 무늬 바탕 위에 올린 시험 화면도 따로 만들었다.
- 찾은 것
  1. **사각 자국 (모든 버튼 공통)**: PillButton 이 알약을 그리기 전에 자기 사각 영역을 부모 BackColor 한 색으로 칠했다.
     부모가 BackColor 와 다른 것을 그리는 곳(카드 테두리·띠·바닥 줄)에서 버튼 둘레가 사각형으로 끊기고
     가장자리에 선 조각이 남았다.
  2. 마우스를 올려도 아무 변화가 없고, 주요 버튼(파랑)은 눌러도 색이 그대로였다.
  3. 키보드 초점 표시가 전혀 없었다.
  4. 메뉴·대화상자가 마우스를 가져가면 MouseUp 이 오지 않아 누름 색이 남을 수 있었다.
  5. 월간 보드 우클릭 메뉴와 알림 영역 아이콘 메뉴는 여전히 Windows 기본 모양이었다.
- 결정 (PillButton 한 곳에서 모든 버튼에 적용)
  - 알약 바깥은 부모가 실제로 그린 그림(배경+Paint)을 그대로 깐다. 한 색 사각 칠하기를 없앴다.
  - 상태 규칙 하나: 꺼짐 > 눌림 > 올림 > 보통.
    보통 버튼은 흰색 → 올림 #f5f5f5 → 누름 #e5e5e5, 주요 버튼은 #155dfc → #1447e6 → #193cb8. 꺼짐은 회색, 올림 없음.
  - 키보드 초점일 때만(마우스 클릭 뒤에는 아님) 알약을 따라가는 2px 테(#8ec5ff, 웹의 ring).
  - 마우스 캡처를 잃거나 초점·보임이 바뀌면 누름·올림을 푼다. 오른쪽 클릭은 누름으로 보지 않는다.
  - 기본 버튼(Enter) 굵은 테는 쓰지 않는다. 꺼진 버튼은 손 모양 커서를 쓰지 않는다.
  - 모든 컨텍스트 메뉴(팝업 ⋯, 월간 보드, 알림 영역 아이콘)에 `Ui.메뉴꾸미기` 를 적용.
- 시험: Smoke GUI-6 (사각 모서리 픽셀이 부모 그림 색, 상태 전환 9가지, 기본 버튼 테 없음, 초점 없으면 테 없음).

## 3-4. 사용자 요청 반영 (2026-09-16 저녁)

- 행동 문구: 신고하기 → 신고완료, 납부하기 → 납부완료 (ADR-0005 개정). 팝업과 웹이 같은 문구를 쓴다.
- 홈페이지 버튼: 예전에는 끝나지 않은 건에서만, 그것도 '문서 열기' 자리를 대신해 보였다.
  그래서 지난 달 항목(부가세 4월)에 주소를 넣어도 어느 탭에도 버튼이 없었다.
  이제 주소가 있으면 상태와 상관없이 받은 알림(카드·오래 밀린 건)·이번 달·연간·이력 탭에 따로 보이고,
  '문서 열기' 는 끝나지 않은 건에 그대로 남는다. 탭을 열 때마다 서버에서 새로 읽으므로 저장 즉시 반영된다.
- 팝업 접힘: '기한 알림 N건' 만 남기고 날짜·경고·설정·접기 버튼을 숨긴다. 접힌 줄 어디를 눌러도 펼쳐진다.

## 3-5. 접힌 상태의 버튼과 접기 애니메이션

- 접힌 상태에서도 설정(톱니)·펼치기(▴) 버튼은 보인다. 날짜·자료 확인 경고만 숨긴다 (3-4 의 결정을 사용자 요청으로 조정).
  '눌러서 펼치기' 풍선과 손 모양 커서는 접힌 상태에서만.
- 접기·펼치기는 200ms 동안 높이를 ease-out cubic(1-(1-t)^3) 으로 바꾼다. 아래 끝은 매 프레임 작업 표시줄에 붙은 채.
  - 10ms 타이머 + Stopwatch 로 경과 시간 기준 (프레임이 밀려도 200ms 에 끝남).
  - 도는 중에 다시 누르면 지금 높이에서 반대 방향으로 이어서 움직인다.
  - Windows '애니메이션 효과' 가 꺼져 있거나 창이 아직 안 보이면 곧바로 바뀐다.
  - 첫 구현에서 펼칠 때 새로 드러난 카드 영역이 1~2 프레임 검게 비쳤다(실제 창을 프레임별로 떠서 확인).
    크기를 바꿀 때마다 RedrawWindow(ALLCHILDREN|UPDATENOW) 로 자식까지 즉시 그려 없앴다.
- 시험: Smoke GUI-3(접혀도 설정·펼치기 버튼 보이기 요청 유지), GUI-7(곡선 끝점·단조 증가·중간 높이·되돌리기·끝나면 정확한 높이·아래 끝 고정).

## 3-6. 팝업 등장 애니메이션

- 처음 뜰 때 제자리보다 16px 아래에서 220ms 동안 떠오르며 투명 → 불투명(ease-out cubic). 끝나면 정확히 제자리·완전 불투명.
- OnLoad(화면에 그리기 전)에서 투명·아래로 옮겨 두어 제자리에서 한 번 번쩍이지 않는다.
  Windows '애니메이션 효과' 가 꺼져 있으면 쓰지 않는다.
- 떠오르는 중에 접기를 누르면 먼저 제자리·불투명으로 끝낸 뒤 접는다 — 접기는 아래 끝을 기준으로 하므로.
- 떠오르는 중에 다시 시작해도 처음 기억한 최종 자리를 쓴다 (시험에서 잡힌 버그: 중간 위치를 최종 자리로 기억해 2px 어긋남).
- 실측(실제 창): 0ms top=548·투명 → 98ms top=536·알파 196 → 163ms top=532·알파 247 → 264ms 제자리·불투명.
- 시험: Smoke GUI-8 (시작 투명·16px 아래, 중간, 떠오르는 중 접기, 끝나면 제자리, 끝난 뒤 호출 무시).
- 나머지 애니메이션 후보(카드 슬라이드, 단계 점 채우기 등 11가지)는 보류 — 로컬 위키 .omc/wiki "납부 알림 — 애니메이션 추가 후보".

## 4. 항목 창 옮기기

- 항목 추가·수정 창의 머리(제목 줄)를 끌면 창이 따라 움직인다(`hooks/use-draggable.ts`).
  가운데에서 옮긴 거리만 들고 있다가 다시 열면 가운데로 돌아온다. 머리가 화면 밖으로 나가지 않게 가둔다.
- shadcn Dialog 는 그대로 쓰고 `left/top` 만 바꾼다 — 열림 애니메이션(transform)과 겹치지 않게.
