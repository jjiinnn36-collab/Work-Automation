# ADR-0023 ERP 차입 스케줄 가져오기, 항목 유효연도 (스키마 4판)

- 상태: 채택 (1단계 — 가져오기·등록. 만기 자동 연장·원장 대사는 다음 단계)
- 날짜: 2026-09-17
- 요청: "수기 입력을 최대한 줄이고 자동화" — 차입금 이자는 ERP 스케줄 파일을 올리면 지급일·지급액이 자동으로 잡히게
- 관련: ADR-0006(이관 절차), ADR-0010(분할 묶음), ADR-0013(엑셀 입력 경로 제거), ADR-0015(사용자설정 흐름)

## 맥락

- 차입금 이자는 차입일 기준 **분기마다 한 번** 낸다. 회계는 매월 말 경과이자를 '미지급비용_이자비용' 으로 인식하고,
  분기가 되는 날 쌓인 경과이자를 한꺼번에 낸다. 지급일이 휴일이면 다음 영업일에 낸다.
- ERP 차입관리 지급스케줄(양식: `차입관리스케줄 양식.xlsx`)은 월말 경과이자 행과, 분기 달에 **지급일까지 끊은 조각 행**으로 되어 있다.
  양식 분석 결과 분기 합(월말 3행 + 조각 1행)은 액면 × 이율 ÷ 4 와 정확히 같고, 네 분기 합은 합계행(Σ)과 같다.
- 항목 모델은 "매년 반복되는 월·일" 이라, 날짜가 박혀 있고 끝이 있는 일정을 담지 못했다.
- 사용자 결정 (2026-09-17)
  - 지급일·만기는 **ERP 스케줄 날짜를 그대로** 따른다 (예: 1년 후 9/4 가 토요일이라 ERP 가 9/3 으로 잡은 날짜).
  - 한 파일에 여러 건이면 **시트로 구분**한다. 잔액관리번호·마감여부는 쓰지 않는다. 원천징수는 없다.
  - **엑셀(.xlsx)과 CSV 둘 다** 받는다.
  - 만기는 상환 전까지 1년 단위로 자동 연장된다. 상환은 별도 기능으로 나중에 한다.
  - 원장(전표) 대사는 후순위.

## 결정

### 파일 읽기 — `src/SheetReader.cs`
- .NET Framework 에 들어 있는 `System.IO.Compression`(ZipArchive)과 `System.Xml` 로 xlsx 를 읽는다. **추가 DLL 없음** — `build.bat`·`run-tests.bat` 에 `/reference:System.IO.Compression.dll` 만 더했다.
  - 공유 글자·서식 조각 글자(읽는 법 표시 제외)·인라인 글자·수식 결과 글자·숫자(엑셀 저장 그대로)·빈 칸 자리를 지킨다.
  - DTD 금지, 한 부분 64MB·파일 20MB·2만 행·200열 한도 (압축 폭탄·과대 입력 막기).
- CSV 는 UTF-8(BOM 유무) → 안 되면 CP949. 따옴표·따옴표 안 쉼표·줄바꿈, 탭 구분(첫 줄 기준).
- `D0 CF 11 E0` 로 시작하는 파일(암호·문서보안이 걸린 엑셀, 옛 .xls)은 **읽을 수 없다고 이유와 함께** 거절한다
  — "ERP 에서 CSV 로 받거나 보안을 푼 .xlsx 로" 안내.
- ADR-0013 은 **항목 마스터를 엑셀로 넣는 경로**를 없앤 결정이다. 이번 경로는 ERP 스케줄 전용이라 그 결정과 겹치지 않는다.

### 스케줄 해석 — `src/LoanSchedule.cs`
- 머리글 행(처음 15행 안): `기준일자`·`현금흐름구분`·`액면이자금액` 이 있어야 양식으로 본다. `액면금액`·`액면이자율`·`거래처명` 은 있으면 쓴다.
- `신규` 행 = 차입일·액면·이율 (시트에 한 번만), `이자지급` 행 = 이자, `상환` 행 = 최초 만기(원금 지급으로 쓰지 않음), 합계행 = 검산.
- 날짜: `yyyy-MM-dd`·`yyyyMMdd`·`yyyy.MM.dd`·`yyyy/MM/dd`·엑셀 일련번호. 금액: 쉼표·'원' 허용, 원 미만 거절.
- **분기 묶기**: k 회차 기준일 = 차입일 + 3k 개월. 그 앞뒤 7일 안의 이자 행 중 **월말이 아닌 행(조각)을 먼저**, 같으면 기준일에 가까운 행이 지급일.
  지급액 = 직전 지급일 다음 행부터 지급일 행까지의 합. 차입일이 월말 근처라 조각이 없으면 월말 행이 곧 지급일이다.
- 검산: 분기 합이 액면×이율÷4 와 2%(최소 10원) 넘게 다르면 **경고**(막지 않음), 합계행과 이자 합이 다르면 경고.
  회차 지급일을 못 찾거나 마지막 지급일 뒤에 이자 행이 남으면 **그 시트는 등록하지 않는다** — 조용히 틀린 금액을 넣지 않는다.

### 항목 유효연도 — 스키마 4판
- `items.시작연도`, `items.종료연도` (NULL = 제한 없음). `PaymentItem.해당연도(y)`.
- `Scheduler.BuildOccurrences` 한 곳에서 거른다 — 팝업·웹·월간 보드가 모두 이 함수를 쓴다.
- 웹은 유효연도 밖의 해로 온 진행·대기·되돌리기·금액·첨부 요청을 **쓰기 전에** 400 으로 거절한다.
  묶음 화면(`/api/group`)은 그 해에 기한이 있는 회차만 보여 준다.
- 항목 수정 요청에 `startYear`/`endYear` 가 없으면 기존 값을 지킨다 — 화면이 모르는 칸 때문에 회차 기간이 풀리지 않게.
- `loans` 표: 묶음·거래처·차입일(유일)·액면·이율·만기·파일·시트·가져온 일시. 같은 차입건을 다시 올리면 같은 묶음으로 잇는다.
- 3판 → 4판 이관은 칸·표 추가뿐이다. 이관 전 사본을 남긴다 (ADR-0006).
- **5판** (2026-09-18): `loans.차입명`·`loans.약칭`. 새 차입건은 등록할 때 **차입명이 필수**, 약칭은 선택.
  화면의 차입처 자리(항목 목록·이번 달·연간·받은 알림·팝업)에는 **약칭, 비었으면 차입명**을 쓴다 (`Store.차입표시이름`, 둘 다 없던 옛 차입건은 ERP 거래처).
  연장 업로드·같은 파일 다시 올리기는 이름을 보내지 않아도 저장된 이름을 지킨다. 연장 차입건 확인은 여전히 ERP 거래처로 한다.

### 등록 — `POST /api/import/loans?mode=preview|save[&only=시트,…]`
- 본문 = 파일, `X-File-Name` = 파일 이름. 첨부와 같은 CSRF 머리글 규칙 (ADR-0003).
- `preview` 는 아무것도 쓰지 않는다. 시트마다 차입 정보·회차(기간·ERP 지급일·실제 지급일·금액·합산한 행)·상태(새로/이미 있음/금액 다름)·경고,
  건너뛴 시트(빈 시트·양식 아님)와 이유를 돌려준다. 계좌번호 열은 읽어도 응답·저장에 쓰지 않는다.
- `save` 는 고른 시트(`only`)마다 한 트랜잭션(`Store.차입가져오기`)으로:
  - 묶음 = 기존 차입건이면 그 묶음, 아니면 `새항목아이디()` (item-NNNN).
  - 회차 id = `묶음-yyyyMM`(ERP 지급일 기준). **이미 있는 id 는 건드리지 않는다** — 진행 중인 회차나 사람이 고친 금액을 덮어쓰지 않는다.
    금액이 다른 회차는 미리보기에 '금액 다름' 으로만 보인다.
  - 회차 항목: 기관 = 약칭(없으면 차입명), 비용명 = "차입금 이자 N회차", `납부만` 흐름의 버튼(전표 발행 → 납부완료)을 쓰되 첫 지점은 고지서수령이 아니라 **지급액 확인** (`Stages.차입이자`, 사용자 요청 2026-09-18),
    알림 팝업 제목은 회차 번호 없이 '차입금 이자' + 차입처를 옆에 작게 (`PaymentItem.차입` — 읽을 때 loans 표로 정함),
    기한 = ERP 지급일(휴일이면 알림·기한 계산이 다음 영업일로), 알림 5영업일 전, 유효연도 = 지급 연도, 금액규칙 변동,
    비고 = 이자기간만 (`이자기간 2026-06-22~2026-09-21`, 사용자 요청 2026-09-18 — 차입일·액면·이율은 loans 표에 있다).
  - 연도별 금액 = 분기 합, 출처 `ERP 차입스케줄`, 비고 = 합산한 행. 변경 기록 동작 `가져오기`(파일·시트·금액).
  - 저장 후 오늘 알릴 회차가 있으면 팝업을 바로 띄운다 (항목 저장과 같은 규칙).

### 화면
- 항목 관리 → **항목 추가** 에서 먼저 종류(일반 비용 / 차입금 이자)를 고른다. **차입금 이자** 를 누르면 스케줄 올리기 창으로 넘어가고, 왼쪽 위 '뒤로가기' 로 종류 고르기에 돌아온다: 파일 여러 개를 고르면 파일마다 미리보기, 차입건마다 체크(새 회차가 있는 건만 기본 선택),
  회차 표(지급액에 마우스를 올리면 합산한 행), 경고·오류·건너뛴 시트, [등록] (새 회차가 없으면 누를 수 없음).
- 항목 목록은 일반 항목과 차입 회차를 한 표에 보인다 (차입건 탭은 두지 않음, 2026-09-18). 차입 회차에는 묶음 표시(item-NNNN)·유효연도를 붙이지 않는다 — 기한과 비고의 이자기간으로 충분하다.
  일반 항목에 유효연도가 있으면 기한 칸에 `2026년만`·`2026~2028년`. '회차 금액' 은 그 회차의 해로 연다.
- 연장스케줄 업로드는 차입 회차 행의 ⋯ 메뉴에 둔다.

- 저장 요청: `nm=시트|차입명|약칭` (시트마다, 차입명 60자·약칭 20자). 저장 전에 고른 시트 모두의 차입명을 확인하고, 하나라도 없으면 아무것도 쓰지 않고 400.

## 결과

- 차입건 하나를 등록하는 데 사람이 입력하는 칸이 없다: 파일 고르기 → 확인 → 등록.
- ERP 가 연장 스케줄을 내면 같은 파일을 다시 올리면 된다 — 같은 거래처·차입일이면 같은 묶음에 새 회차만 더해진다.
- 남은 일 (다음 단계)
  - 만기 자동 연장: 연장 스케줄이 오기 전에 다음 회차를 예상값(액면×이율÷4)으로 이어 붙이기.
  - 이미 있는 회차의 금액이 달라졌을 때 확인 후 바꾸기(지금은 표시만).
  - 상환 등록, 계정별원장 대사로 '지급전표' 자동 진행 (`docs/research-hometax-filing.md`, 시안 `mockup-web-F4-*`).
