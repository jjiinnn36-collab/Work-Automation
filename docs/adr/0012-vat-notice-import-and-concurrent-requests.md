# ADR-0012 납부서 판독은 별도 프로세스, 웹 요청은 병렬 처리

- 상태: 채택
- 날짜: 2026-09-16
- 관련: AC-W17, AC-W18, AC-W36

## 맥락

부가세 납부서 판독 도구(`tools/import-notice.ps1`)는 Word COM 으로 PDF 텍스트를 뽑고
세목 합계와 문서상 '계' 를 대조한다. 사람이 끌어다 놓는 배치 도구라 확인 질문을 하고 `amounts.tsv` 에 직접 썼다.
웹 명세는 **웹 업로드**로 판독하되 **별도 프로세스**로 실행해 실패·지연에도 서버가 멈추지 않을 것을 요구한다.
그런데 웹 서버는 요청을 한 줄로 처리했다(ADR-0003) — 판독이 90초 걸리면 그동안 화면 전체가 멈춘다.

## 결정

### 판독 도구
- `-Result` 모드: 안내 문구를 끄고 `키<탭>값` 줄만 낸다. **파일을 쓰지 않는다.**
  `ok`, `code`, `message`, `due`, `vat`, `edu`, `farm`, `surcharge`, `sum`, `total`.
  JSON 대신 탭 줄을 쓴 이유: .NET Framework 기본 참조만으로 읽을 수 있다 (추가 DLL 참조 없음).
- `-TextFile` 모드: Word 대신 이미 뽑은 텍스트를 읽는다. 판독·검산 규칙을 Word 없는 PC 에서 시험하기 위해서다.
- 종료 코드는 기존 그대로 (3 부가세 아님, 4 기한 없음, 5 면마다 계 다름, 6 합계≠계).

### 웹
- `POST /api/import/vat` (본문 = PDF, 20MB 이하): `powershell -File import-notice.ps1 -Pdf … -Result` 를 띄우고
  **90초** 기다린다. 넘으면 프로세스를 죽이고 504.
- 결과가 정상이면 **반영을 제안만** 한다: 납부기한 월과 같은 월의 `부가` 항목이 정확히 하나일 때 `{id, year, amount, existing}`.
  저장은 화면에서 사용자가 확인하고 `/api/amount` 로 한다 (기존 도구의 y/N 확인과 같은 자리).
- 검산 불일치·후보 없음·후보 여럿이면 `ok:false` 와 이유, 대조 숫자를 돌려준다.

### 요청 병렬 처리
- `HttpListener` 가 받은 요청을 `ThreadPool` 로 넘긴다. 요청마다 DB 연결을 새로 여는 구조(ADR-0003)라 공유 상태가 없고,
  동시 쓰기는 SQLite 쓰기 잠금 + `busy_timeout 5000` + 원자적 단계 변경(ADR-0004)이 줄 세운다.
  공휴일 갱신 작업 상태만 잠금으로 보호한다.

## 결과

- 느린 판독 중에도 다른 화면 요청이 즉시 응답한다 (WEB-16 에서 3초 한도·1초 이내 응답 확인).
- 배치 파일 경로(`import-notice.bat`)는 그대로 동작한다.

## 검증

`OpsTests` OPS-5 (실제 ps1 을 -TextFile 로: 정상·합계 불일치·면 불일치·부가세 아님·기한 없음),
`WebTests` WEB-16 (제안·거절 사유·502·403·느린 도구 504·판독 중 병렬 응답).
