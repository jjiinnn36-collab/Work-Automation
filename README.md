# 정기 납부 기한 알림

정기적으로 납부·신고해야 하는 항목의 기한을 매일 감시하고, **기한 3영업일 전**에
팝업으로 알린다. 팝업은 '완료' 처리를 해야만 사라지며, 처리 전까지 매일 다시 뜬다.

목표는 **기한 누락 0건**이다. 실제 이체·송금은 하지 않는다.

## 회사 PC에서 시작하기

### 1단계 — 환경 확인 (최초 1회)

`check-env.bat` 을 더블클릭한다. 관리자 권한은 필요 없다.

바탕화면에 `env-check-result.txt` 가 생성되고 메모장으로 열린다.
아래 항목을 확인한다.

| 항목 | 정상 | 문제일 때 |
|------|------|-----------|
| `[6] DOCS_EXEC_OK` | exe 생성·실행 가능 | AppLocker 등으로 차단됨 |
| `[7] WINFORMS_OK` | 팝업 GUI 가능 | GUI 사용 불가 |
| `[11] SCHTASKS_CREATE=OK` | 매일 자동 실행 등록 가능 | `[12]` 시작프로그램으로 대체 |
| `[13] HTTPS=REACHABLE` | 공휴일 자동 갱신 가능 | 공휴일 파일 수동 관리 |

이 파일은 시스템을 변경하지 않는다. 만든 임시 파일은 실행 후 모두 삭제한다.

### 2단계 — 납부 항목 입력

`data/payment-master.sample.tsv` 를 복사해 `data/payment-master.tsv` 를 만들고
실제 납부 항목을 채운다. 엑셀이나 메모장 어느 쪽으로 편집해도 된다.

| 열 | 설명 |
|----|------|
| `id` | 항목 식별자. 겹치지 않게 아무 값이나 |
| `기관` | 금융투자협회, 국세청 등 |
| `비용명` | 부가세, 감독분담금 등 |
| `진행흐름` | `신고납부` / `납부만` / `제출만` — 아래 표 참조 |
| `월` | 1~12 |
| `일` | 날짜 숫자, 또는 말일이면 `EOM` |
| `알림영업일` | 기한 며칠 전에 알릴지. 비우면 기본 `3` |
| `금액규칙` | `고정` / `고지수령` / `전기확정÷4` / `수작업` / `해당없음` |
| `고정금액` | `금액규칙`이 `고정`일 때만 입력 |
| `비고` | 메모 |

### 진행흐름

항목마다 거쳐야 하는 단계가 다르다.

| 진행흐름 | 단계 | 해당 항목 |
|---------|------|----------|
| `신고납부` | 신고 전 → 신고완료 → 전표결재 → 납부완료 | 신고 후 납부하는 세목 |
| `납부만` | 납부 전 → 전표결재 → 납부완료 | 고지서를 받아 납부만 하는 건 |
| `제출만` | 제출 전 → 제출완료 | 산정자료 제출처럼 납부가 없는 건 |

팝업에서 다음 단계 버튼을 누르면 진행되고, 진행 상황은 `data/status.tsv` 에 기록된다.
잘못 눌렀으면 이전 단계로 되돌릴 수 있다.

### 팝업 닫기

표시된 **모든** 건에 대해 아래 둘 중 하나를 선택해야 닫힌다.

- **[단계 진행]** — 다음 단계로 넘어간다
- **[오늘은 대기]** — 오늘은 할 게 없다 (결재 승인 대기 등). 내일 다시 뜬다

창 닫기(X)나 Alt+F4로는 닫히지 않는다. 매일 모든 건을 한 번씩 확인하게 하기 위해서다.

납부완료·제출완료까지 끝낸 건은 **그날 목록에서는 완료 표시로 남고** 다음 날부터 뜨지 않는다.
잘못 눌렀으면 그 자리에서 [되돌리기]로 이전 단계로 되돌린다.

같은 날 프로그램을 다시 실행해도 이미 처리한 건은 다시 묻지 않는다.

### 기한이 지난 건

기한이 지나도 **5영업일까지는** 계속 강제로 뜬다. 그 뒤로는 팝업 위쪽에 요약 한 줄로만
표시되고 처리를 강제하지 않는다. 전체 목록은 `data
un.log` 에 남는다.

이미 늦은 건을 매일 붙잡아도 얻는 게 없고, 그러다 프로그램을 꺼버리면
앞으로의 기한까지 놓치기 때문이다.

`전표결재` 단계는 ERP에 자동으로 상신하지 않는다. 결재를 올렸는지 여부를 표시만 한다.

`EOM`(말일)을 쓰면 2월이 윤년인지 자동으로 판단한다. `2/28` 로 직접 적으면
윤년에 하루 어긋나므로 말일 기한은 반드시 `EOM` 으로 적는다.

기한일이 토·일·공휴일이면 **다음 영업일**로 자동 보정된다.

### 알림 시점 바꾸기

`알림영업일` 열의 숫자만 고치면 된다. 기본은 3영업일 전이고, 금액을 직접 산정해야 하는
항목처럼 준비 시간이 더 필요한 건은 값을 늘린다. 비워두면 3이 적용된다.

권장 기준:

| 항목 성격 | 알림 |
|----------|------|
| 금액을 직접 산정해야 하는 건 | **5영업일 전** |
| 고지서를 받아 그대로 납부하는 건 | 3영업일 전 |

항목마다 알림일이 다르므로 여러 건이 같은 날 겹칠 수 있다.
그런 날은 팝업에 목록으로 함께 표시되고, 건별로 따로 완료 체크한다.

### 3단계 — 공휴일 자료

`data\holidays.tsv` 에 **2025~2027년 공휴일 66건이 이미 채워져 있다.** 그대로 쓰면 된다.
한국천문연구원 특일정보 API에서 받아온 공식 자료이며, 대체공휴일과
2026년부터 부활한 제헌절, 2026년부터 공휴일이 된 노동절까지 반영되어 있다.

**2028년 이후**에는 파일을 갱신해야 한다. 두 가지 방법이 있다.

- **직접 입력** — `data\holidays.tsv` 에 `날짜<탭>명칭` 형식으로 한 줄씩 추가한다. 연 1회면 충분하다.
- **자동 갱신** — [공공데이터포털](https://www.data.go.kr) 인증키를 `datapikey.txt` 에 한 줄로 저장한다.
  이후 30일마다 자동으로 받아와 갱신한다.

  인증키는 계정당 하나지만, **API마다 활용신청을 따로 해야 그 키가 동작한다.**
  1. data.go.kr 로그인 → *한국천문연구원_특일 정보* 검색 → **활용신청** (자동승인)
  2. 마이페이지 → 오픈API → 개발계정 에서 상태가 *승인* 인지 확인
  3. 신청 직후에는 반영까지 시간이 걸릴 수 있다

  활용신청이 안 된 상태로 호출하면 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` 가 돌아온다.
  프로그램은 이 경우 무엇을 해야 하는지 팝업에 안내하고, 기존 공휴일 자료로 계속 동작한다.

자료가 없는 연도는 주말만 반영해 계산하고 **알림을 이틀 앞당기며** 팝업에 경고를 띄운다.
공휴일을 모르면 알림이 늦어질 수 있어 안전한 쪽으로 기울인 것이다.

임시공휴일이 새로 생기면 그 줄만 추가하면 된다.

### 4단계 — 빌드

`build.bat` 을 더블클릭하면 exe가 만들어진다. 별도 설치는 필요 없다.

빌드 후 `run-tests.bat` 을 실행하면 날짜 계산이 제대로 되는지 확인할 수 있다.
연간 일정표가 함께 출력되므로 눈으로 검산해 볼 수 있다.
다른 연도를 보려면 `run-tests.bat 2027` 처럼 연도를 붙인다.

### 5단계 — 자동 실행 등록

`install-task.bat` 을 실행하면 매일 오전 9시에 자동 실행되도록 등록된다.
PC가 꺼져 있어 실행을 놓친 날은 켜진 뒤 곧바로 실행된다.

회사 정책으로 작업 스케줄러 등록이 막혀 있으면 시작프로그램 등록으로 자동 대체된다.
그것도 막히면 안내 메시지가 나오고, 그때는 `PaymentAlert.exe` 를 직접 실행해 쓴다.

해제하려면 `schtasks /delete /tn "납부기한알림" /f`

## 외부에 올리지 않는 파일

`data/payment-master.tsv` 에는 사내 납부 일정과 금액이 들어간다.
`.gitignore` 에 등록되어 있어 커밋되지 않는다. 이 설정을 풀지 않는다.

## 공휴일 데이터

공공데이터포털 한국천문연구원 특일정보 API로 공휴일을 받아 `data/` 에 캐시한다.

- 갱신은 연 1회 + 월 1회. 매일 실행할 때는 캐시만 읽으므로 네트워크에 의존하지 않는다
- API 호출이 실패해도 기존 캐시로 정상 동작한다
- 사내에서 API가 차단되어 있으면 캐시 파일을 직접 넣어도 된다
- 캐시가 오래되면 팝업에 경과일수 경고가 표시된다

네트워크가 실패해도 알림은 멈추지 않는다.
